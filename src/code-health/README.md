# Code-health storage and collection seams

This directory contains Heimdall's local persistence, bounded producer admission, and read-only query seams for the frozen Code Health v1 contract. The read-only `/code-health` page and `/api/code-health` endpoint use these stored views; see [`../../docs/code-health.md`](../../docs/code-health.md) for the user-facing contract, configuration boundaries, retention and rollback.

Objective collection is off by default. `collectObjectiveReports({ db, config, transport, clock })` only performs work when `config.enabled === true` and receives a `transport` with authenticated `listArtifacts` and `downloadArtifact` methods. Production uses `createGitHubTransport()`, a read-only adapter over the existing configured `gh` CLI. Its requests are pinned to `github.com`, the two registered repositories, and `.github/workflows/code-health.yml`; archive downloads use only validated numeric artifact IDs. The adapter bounds recent runs, pages, candidates, output size, and command time, with a 60-second per-repository deadline across metadata scans and downloads. It binds each artifact to the explicit run attempt using matching repository/head metadata, the attempt's job-time window and a stable run readback. Truncated or ambiguous scans return partial collection status and persist the source as `incomplete`, preserving earlier evidence; old-attempt artifacts are never relabeled. The collector passes the transport an `isSettled(runId, attempt)` predicate; settled run attempts are dropped before the 10-run eligible limit and before any per-run request or download, so only more than 10 *unsettled* eligible runs count as truncation. Without the predicate the transport behaves as an unfiltered scan. Every other `incomplete` signal (page limit, revision races, ambiguous jobs or artifacts, duplicate artifact IDs, scan deadline) is unchanged. The archive gate then binds manifest/snapshot commits to the authenticated head SHA, validates each metric's run reference and attempt, and applies the frozen schema plus semantic validators. The runtime config's exact `{"sources":[]}` shape enables this objective path without configuring subjective Munin sources; configured nonempty sources retain the authenticated reconciliation path.

The accepted source repositories and their slots come from the hash-pinned registries in `registries/`. Snapshot IDs remain opaque contract identifiers; Heimdall enforces immutable ID replay/collision behavior but does not reimplement either producer's ID hash. SagaScript metric sources must use `ref:github-run-{runId}-attempt-{attempt}`. Gille Inference metric sources must use the exact collection ref for the authenticated run and attempt: `complexity`, `knip`, `coverage`, or `ci` suffixes for the corresponding slots. `source.attempt` must match the authenticated attempt. Registered slot fields (language, platform, features, scope and metric versions) are checked. `scope_digest` must satisfy the frozen digest schema and is retained in the frozen `seriesKey`; Heimdall does not claim to recompute producer config/scope digests. A digest change creates a separate series key rather than being silently merged.

The artifact parser accepts the producers' closed manifest and evidence-index formats. It rejects unsafe or duplicate ZIP members, links and special files, unsupported compression, excessive sizes/counts, unknown files and malformed provenance. SagaScript's `scope-registry.json` must equal the pinned registry, except for the membership of the `complexity.scopes` file lists, which may vary per commit and are validated structurally: the same scope names, bounded non-empty lists, unique safe relative paths, the pinned file extensions, and no file in two scopes. It is treated as data and is never executed. Missing registered slots are persisted as explicit unknown gaps.

Run attempts are tracked in `code_health_objective_runs` (one row per repository, run ID and attempt). A run attempt is *settled* once its artifact is admitted, including a replay that inserts nothing new; that `admitted` row is written in the admission transaction. A rejected run stays unsettled and is retried every cycle, so a later parser fix can recover it; its row records `rejected`, a stage-based reason code (`transport-provenance-invalid`, `artifact-download-failed`, `artifact-size-mismatch`, `artifact-parse-rejected` or `admission-rejected`) and the latest handled time, and becomes `admitted` if a later cycle admits it. Raw error messages are never stored. Admitted run rows expire six calendar months after they were last handled, far beyond the 30-day listing window. A rejected run row expires 24 hours after its latest retry, so the rejected rows on record — and the rejection count, time and reason code read from them — are the runs the collector is still retrying, not ones that have aged out of the listing window. Both are removed by `pruneExpiredEvidence`. An existing database starts with an empty runs table and drains its backlog 10 runs per cycle.

Each cycle writes exactly one collector-level audit row per source, last, by precedence: `unavailable` (the listing failed) > `rejected` (any candidate was rejected this cycle) > `incomplete` (a fail-closed truncation or ambiguity signal) > `committed` (new snapshots were stored) > `current` (the scan was complete and nothing needed admitting) > `no-artifacts` (no eligible run had an artifact). Admissions that insert snapshots also keep their in-transaction `committed` row with the inserted count; replay-only admissions and individual rejections write no audit row. After each collector cycle, `src/code-health-alerts.js` raises one `warning` alert (category `code-health`, never critical, so no push notification) per enabled and configured repository whose newest admitted run is older than the shortest registered slot `freshness_ms` cap, and clears it once a fresher run is admitted. With no admission on record it does not alert, because the age is unknown. Objective snapshots expire six calendar months after collection. `getObjectiveHistory(db, { repoOwner, repoName, days, asOf })` accepts only 30-, 90-, or 365-day windows; expired history is omitted even when the requested window is longer than retention. `readObjectiveSourceState(db, { repoOwner, repoName, enabled, configured })` returns the last attempted status/time, last successful sample time and a static error code without contacting a source. It also returns `last_rejection_at` and `last_rejection_code` for the most recent rejected run still on record, `rejected_runs` (currently rejected, unsettled run attempts) and `last_admitted_run_at` (creation time of the newest admitted run, falling back to the newest snapshot collection time). The page and `GET /api/code-health` (`objectiveCollection`) show these bounded fields; no producer-controlled text is rendered.

Subjective reconciliation uses the existing Munin RPC path: `reconcileSubjectiveEvidence(db, config, { rpc, now })`. The same default-off runtime config supplies each pinned repository's namespace and producer principal. Tests inject the RPC method; production uses the existing authenticated Munin client only during an explicitly enabled collector cycle. Each request calls `memory_code_health` with required `action: "export"`, the configured namespace and producer principal, exact repo/rubric filters, and a bounded page size. The producer principal must be authorized by the authenticated Munin caller. Heimdall checks the returned namespace, producer and filter hash, plus page watermark, record totals, references, retention metadata and cursor uniqueness. The filter hash follows Munin's canonical `{ namespace, producer, filters }` shape; every omitted filter is `null`, including task, time and model filters. Only a final page marked complete and `complete-authorized-retained-set` can replace the local source set. Failed, invalidated or partial exports keep existing non-expired data. Local expiry still runs during collector cycles, and dependent records are removed when referenced context expires.

`readSubjectiveEvidence(db, config, { now })` is an async, bounded, read-only view used by the page and API. It does not call Munin, load credentials or trigger collection. It returns the last successful source metadata, primary records and their authoritative retention metadata, retained context, a frozen `aggregateRecords` result, and collection status (`unconfigured`, `disabled`, `not-collected`, `committed`, `incomplete`, or `rejected`) with last attempt/success times and a static error code. If no valid source config has ever been supplied, it returns an explicit `unconfigured` state and empty evidence. Expected-attempt inventory is deliberately omitted, so participation denominator/fraction stay unknown.

Focused synthetic backend and runtime tests live under `test/code-health-*.test.js`; the migration's focused assertions are under the `openDatabase` tests in `test/db.test.js`. The runtime is implemented but remains disabled unless the owner supplies a valid private source config and sets the explicit gate. This work does not activate the gate or claim live GitHub/Munin collection. UI rendering must use these read-only query methods and must not collect during a request.
