# Code health

`/code-health` and `GET /api/code-health` are read-only views of evidence already stored in Heimdall. Rendering never contacts GitHub or Munin, loads credentials, invokes collectors, or starts a task. The five objective measures remain separate from subjective worker observations. Unknown, stale, failed, unsupported, and incomplete evidence stays explicit; absent sprint markers and unavailable participation denominators are not inferred.

Both source paths are disabled by default, and the page itself never enables them. The normal collector loads the default-off runtime config and calls the code-health collectors near the end of its cycle. Source collection requires `HEIMDALL_CODE_HEALTH=on` and a valid private JSON config named by `HEIMDALL_CODE_HEALTH_CONFIG`. The config has one top-level `sources` array. An empty array (`{"sources":[]}`) is the explicit objective-only mode: both pinned objective repositories are collected, no subjective source is configured, and no Munin reconciliation is attempted. When sources are present, each has exactly `repoOwner`, `repoName`, `namespace`, and `producerPrincipalId`; owner and repository must match the pinned registry. Heimdall fixes the rubric to `changeability-1.0`. The config accepts no URLs, commands, credentials, or extra fields and is limited to 16 KiB. A missing or invalid config while the gate is on is reported as rejected and performs no collection. Keep the config and its location out of the repository.

Objective reports use the existing configured `gh` CLI with fixed `github.com` requests and GET only. The adapter pins both repository and workflow path, scans at most two pages of 25 completed runs per repository from the last 30 days, and handles at most ten eligible runs per repository in a cycle. It fetches at most two pages of 100 attempt jobs and one page of 25 artifacts per eligible run. Each repository scan, including its artifact downloads, has a 60-second total deadline; individual `gh` commands are limited to ten seconds and clamped to the remaining budget. Deadline expiry and other truncation are surfaced as partial collection and persisted with the source's `incomplete` status so older evidence remains visible. Other source failures, ambiguous job timestamps, an artifact outside its attempt's job window, mismatched provider metadata, or a changing run revision are surfaced as unavailable, incomplete, or rejected collection. The artifact API does not provide `run_attempt`; Heimdall binds it using the exact attempt endpoint, matching run and artifact metadata, the job-time window, and a stable run readback. It never follows a producer-supplied URL or treats a newer attempt number as proof that an older artifact belongs to that attempt. GitHub authentication must already be configured for `gh`; Heimdall does not log in or provision credentials.

Subjective reconciliation uses the existing authenticated Munin RPC helper. The authenticated caller must already be authorized for each configured producer principal. Neither read route contacts GitHub or Munin, reads credentials, or starts collection. An operator can run `npm run collect:code-health` for an explicit standalone collection cycle; it remains a no-op unless the same gate and valid config are present. The runtime is implemented but not activated or live-verified by this change.

The subjective reconciliation seam remains `reconcileSubjectiveEvidence(db, config, { rpc, now })`. Its library default is `{ enabled: false }`. Production config is normalized into its fixed source shape, with `enabled` derived only from the explicit gate. The UI reads through `readSubjectiveEvidence` using that same parsed identity, so valid retained data remains associated with the right source while collection is disabled.

Objective snapshots and missing-slot gaps expire six calendar months after collection. Subjective records use Munin's returned `expires_at`, which Heimdall validates against the six-calendar-month maximum. Reads omit expired rows; physical pruning is use-driven by objective collection or subjective reconciliation, not a background timer. A 365-day view still requests that window, while older records may be absent because each record expires from its collection date.

Database migration v15 adds the code-health tables and indexes without replacing existing data. A safe rollback is to disable or remove the Code health feature in application code and retain these additive tables. There is no automatic downgrade; do not lower `user_version` or drop the tables as part of an application rollback.

The actual non-static Gille and SagaScript producer bundles pass Heimdall's bounded archive parser in local synthetic interoperability checks. A Gille static artifact produced on macOS remains correctly rejected because its source platform differs from the registered `linux-x64` cohort. Acceptance of a real Linux CI artifact and authorized live subjective Munin end-to-end collection remain pending. The synthetic preview is fixture-only and does not represent live acceptance.

To reverse runtime integration, set `HEIMDALL_CODE_HEALTH` to a value other than `on` and revert the runtime source changes. Keep the additive v15 tables and their retained evidence; do not lower `user_version` or drop the tables as part of rollback. Collection and expiry outcomes are written to the existing code-health audit table.
