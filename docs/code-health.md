# Code health

`/code-health` and `GET /api/code-health` are read-only views of evidence already stored in Heimdall. Rendering never contacts GitHub or Munin, loads credentials, invokes collectors, or starts a task. The five objective measures remain separate from subjective worker observations. Unknown, stale, failed, unsupported, and incomplete evidence stays explicit; absent sprint markers and unavailable participation denominators are not inferred.

Both source paths are disabled or unavailable by default, and the page itself does not enable them. Heimdall has no authenticated GitHub artifact adapter or runtime schedule for objective reports. The existing collector seam is `collectObjectiveReports({ db, config: { enabled: true }, transport, clock })`; `transport` must implement authenticated `listArtifacts({ owner, repository, workflowPath, branch, events, artifactName })` and `downloadArtifact({ owner, repository, artifactId })`. There is no production transport or UI trigger wired to this seam.

The subjective reconciliation seam is `reconcileSubjectiveEvidence(db, config, { rpc, now })`. Its default is `{ enabled: false }`. An explicitly supplied config must provide `enabled: true`, `namespace`, `producerPrincipalId`, `repoOwner`, `repoName`, and `rubricVersion: "changeability-1.0"`. The repository owner/name must match a pinned producer registry, and the authenticated Munin caller must be authorized for `producerPrincipalId`. The `rpc` function is a test/integration seam; no subjective source configuration is currently wired into production startup. The UI reads only through `readSubjectiveEvidence` and uses the disabled default.

Objective snapshots and missing-slot gaps expire six calendar months after collection. Subjective records use Munin's returned `expires_at`, which Heimdall validates against the six-calendar-month maximum. Reads omit expired rows; physical pruning is use-driven by objective collection or subjective reconciliation, not a background timer. A 365-day view still requests that window, while older records may be absent because each record expires from its collection date.

Database migration v15 adds the code-health tables and indexes without replacing existing data. A safe rollback is to disable or remove the Code health feature in application code and retain these additive tables. There is no automatic downgrade; do not lower `user_version` or drop the tables as part of an application rollback.

The actual non-static Gille and SagaScript producer bundles pass Heimdall's bounded archive parser in local synthetic interoperability checks. A Gille static artifact produced on macOS remains correctly rejected because its source platform differs from the registered `linux-x64` cohort. Acceptance of a real Linux CI artifact, production GitHub transport/scheduling, and authorized subjective Munin end-to-end collection remain pending. The synthetic preview is fixture-only and does not represent live acceptance.
